# Движок

Общая основа для наших изометрических игр в пиксельном 2.5D. Вырос из «Двора у пятиэтажек» и растёт вместе с играми: сюда переезжает то, что нужно больше чем одной игре. Двор остаётся полигоном для новых функций, а `poligon/` показывает всё, что движок умеет, без единой строчки кода двора.

## Как он рисует

1. Всё в мире — 3D-модели, собранные кодом из простых форм: коробки, цилиндры, «лофты» из колец, многоугольники, карточки, линии в 1 пиксель.
2. Камера ортографическая, изометрия 2:1: метр по земле — 54 пикселя по диагонали клетки, герой ростом около 120 пикселей. Камера никогда не поворачивается — на этом держатся трава и листва (см. ниже).
3. Сцена рисуется в низком разрешении («пиксели арта») и растягивается без сглаживания — отсюда пиксель-арт. Кадр обновляется 12 раз в секунду.
4. Свет ступенчатый: у каждого материала пять тонов (от тени к блику), шейдер выбирает тон, а узоры (кирпич, листва, окна, трава, ржавчина…) рисуются прямо в шейдере.
5. **Солнце.** Каждый кадр сначала рисуется карта глубины со стороны солнца, подогнанная под то, что видит камера (размер постоянный, сдвиг — целыми текселями, поэтому тени не дрожат при движении). Всё, что попало в тень, берёт тон «в тени»: `min(тон, мягкий свет неба)`. Тени падают на землю, стены и героя; листва пропускает солнце пятнами.
6. **Земля** — большая картинка, раскрашенная попиксельно по карте клеток (трава штрихами, тропинки, мусор у лавочек). Она загружается в видеокарту и рисуется внутри сцены вторым проходом: так земля тоже темнеет в тени, а сетка и кольцо цели рисуются на ней.
7. Второй проход рисует контуры, затемняет стыки и подсвечивает предмет под пальцем. Номера предметов пишутся в отдельный буфер — по нему работает нажатие на предмет.
8. **Ветер.** У материала может быть `wind: [размах в метрах, 1 / высота, скорость, доля дрожи]` — вершины качаются вдоль горизонтали экрана, сильнее вверху; порывы бегут по двору волной. Тени качаются вместе с листвой.
9. Эффекты (дым, пыль, искры, гильзы, листья, бабочки) — 2D-слой поверх сцены в пикселях арта. Дым и пыль — клубы-спрайты с растром вместо прозрачности.
10. **Время суток** (`src/world/daytime.js`). Одни часы на всю игру. Локация говорит, где её солнце в какой-то час (`sun` в `sunAt`, по умолчанию 14:00), дальше солнце само идёт по небу: утром низко с одной стороны, днём высоко, вечером низко с другой; ночью свет даёт луна. Остальное берётся из ключей `DAY_KEYS` по часу: оттенок освещённого и теневого, сила теней, насыщенность, сколько горит фонарей и окон, утренний туман, цвет воздуха вокруг карты, холод (виден пар изо рта). Шейдер красит всё этими оттенками, фонари и фары добавляют свой свет ступенями с растровым краем, окна ночью светятся сами (у каждого своё «включено/выключено», иногда — синий мерцающий телевизор), туман лежит низко и тянется по ветру. Фонари в каталоге: у предмета `lamp: { at, r, col, k, cone, kind }`. Без часов (карточки каталога, портрет) всё выглядит как в полдень.

## Как устроен код

Каждый файл — модуль: в начале он перечисляет, что берёт у других (`import { a, b } from '…';`), а то, что отдаёт другим, помечает словом `export`. Из каких модулей состоит игра, перечисляет её вход — `<игра>/src/main.js`; в `build.json` указан только он.

Сборка (`tools/build.mjs`) ставит модули в том порядке, в каком их запустил бы сам браузер (каждый — после тех, у кого он берёт), убирает строки `import` и слово `export` и склеивает всё в один скрипт внутри общей функции. Поэтому имена верхнего уровня должны быть разными во всей игре. Рядом сборка кладёт `build/<игра>.dev.html` — ту же игру прямо из модулей, без склейки: так браузер сам проверяет каждый импорт.

Правила модулей (их проверяет `node tools/deps.mjs <игра>` — в отчёте должно быть «нет» по всем пунктам):

1. **Без кругов.** Модуль берёт только у тех, кто запускается раньше. Если нижнему слою нужно что-то сообщить верхнему, он объявляет крючок (список функций), а верхний на него подписывается — так устроены `GAME`, `LOC_HOOKS`, `HERO_EVENTS`, `MACHINE_HOOKS`, `PEOPLE_HOOKS`.
2. **Чужое не меняют.** В импортированную переменную не пишут: её хозяин даёт функцию (`setMap`, `setHero`, `rebuildHero`, `newId`, `redraw`, `recenter`, `setRaw`…). Поля объектов (`hero.x`, `MAP.exits`) менять можно.
3. **Слои.** Движок (`engine/`) ничего не берёт у игр. **Ядро** нужно любой игре; **библиотека предметов**, **шагающие машины** и **люди** — по желанию, игра подключает их строчками в своём `main.js`. Ядро ничего не знает ни о библиотеке, ни о машинах, ни о людях, ни об игре — всё приходит к нему через крючки.
4. **Простая форма.** Импорт — одна строка в начале файла (после заголовка-комментария), только вида `{ имя, имя }`; экспорт — только слово `export` перед `function`, `const`, `let` или `class`. Лишних импортов не держат.

Как добавить модуль: написать файл, вверху перечислить импорты, пометить `export` то, что нужно другим, и вписать строку `import './путь.js';` в `main.js` каждой игры, которой он нужен, — после модулей, у которых он берёт. Потом `node tools/deps.mjs <игра> --fix` (допишет импорты, которых не хватает), `node tools/deps.mjs <игра>` и `node tools/build.mjs <игра>`.

### Люди (`src/people/`)

Другие персонажи: стоят, замечают героя, разговаривают, ходят за ним, торгуют. Подключаются пятью модулями, по порядку: `items`, `look`, `people`, `talk`, `trade`.

| Файл | Что внутри |
|---|---|
| `items` | типы вещей `itemType(id, { name, note, price, gear, icon })`, инвентари (`INV.hero`, у людей — `p.inv`): `invAdd`, `invTake`, `invCount`; иконки из 3D-моделей (`itemIcon`), сетка вещей для страницы (`invGrid`) |
| `look` | внешность: человек стоит на скелете героя, одет в «вещи» (`PERSON_PIECES`), части одной кости и материала склеиваются; комплект КЗУ по эскизу игрока (`KZU_LOOK`) |
| `people` | `addPerson(def)`: человек в локации, его нажатие и панель «рядом», взгляд на героя, «Идём со мной» / «Жди здесь» / «Ступай на место», лавочка рядом с героем, переходы через выходы, реплики над головой |
| `talk` | разговоры: `DIALOGS[id] = { start, nodes }`, у реплики — варианты ответа с условиями и действиями; панель с портретом встаёт на место панели «рядом» |
| `trade` | окно обмена: свои вещи на его, разница рублями, сдача, отказы (`trade.wants`), после сделки — `PEOPLE_HOOKS.traded` |

Как устроен человек:

1. **Тело.** Те же кости и позы, что у героя (`buildPose`, `evalBones`): ходьба, бег, сидя, жесты при разговоре (`applyTalk`), поворот головы (`headYaw`). Свои пропорции — в `look.dims`.
2. **Ум** — режим: `post` (стоит на месте, поворачивает голову к герою, здоровается, оглядывается, после того как отошёл в сторону — возвращается), `follow` (держится в полутора метрах, догоняет бегом, садится на соседнее место лавочки, уходит с героем через выходы), `wait`, `home` (идёт на своё место, если надо — через выход в другую локацию), `talk`.
3. **Рисование** — снимок 12 раз в секунду, как у героя и машин (`GAME.tick`, `GAME.items`, `GAME.key`). У частей флаг 16: ночью человек остаётся различимым, как герой.
4. **Реплики над головой** — `def.barks`: `hello`, `follow`, `wait`, `home`, `sit`, `arrive(loc)`, `idle`. Пузырь — элемент страницы над сценой, идёт за головой.
5. **Разговор.** Узел: `{ say, run(p), opts }`, ответ: `{ say, to, when(p), run(p) }`. Ответ без `to` заканчивает разговор. `talkSeen(p, узел)` — сколько раз узел уже звучал (первая встреча или нет).
6. **Торговля.** `def.trade = { buy: 0.6, sell: 1, wants(t) → true или почему нет, says }`. Сделка проходит, если отданное стоит не меньше взятого; разницу он возвращает деньгами, сколько у него есть.

Панель разговора, окно обмена и пузыри модуль добавляет на страницу сам, со своими стилями на цветах страницы. Посмотреть человека со всех сторон: `node tools/person-sheet.mjs лист.png --game=poligon`.

### Как игра подключается к движку

1. **Каталог.** Свои предметы игра кладёт в `CATALOG`: `Object.assign(CATALOG, { swing: { build, name, size, note, …флаги } })`. Флаги, которые читает движок: `xray` (большой — герой виден сквозь него силуэтом), `hug` (бурьян гуще вдоль него), `litter` (сколько окурков и пробок вокруг), `bounds: false` (не учитывать в общем виде), `leafy(def)` (роняет листья), `midges` (над ним мошкара вечером), `near(inst, x, z)` (расстояние до края, если это не его препятствия).
2. **Что с чем делать.** `USE[тип] = { name(inst), note(inst), acts(inst) → [{ label, run, off }], active(def), short(inst) }` (`short` — имя в фишке «рядом: …», если строчные буквы не годятся). Нажимаются только предметы, у которых есть `USE`. Для приказов герою есть готовые: `walkTo`, `goSit`, `goSpot`, `plan(...)` с очередью (`path`, `goto`, `face`, `turned`, `act`, `reach`, `shoot`, `throw`, `call`…), занятия `look` и `kneel`. Свои занятия игра добавляет в `ACT` (качели, лестницы).
3. **Крючки** (`src/core/game.js`): `GAME.update` (свой шаг мира), `GAME.items` (подвижные части в кадре), `GAME.key` (меняется, когда они двигаются), `GAME.tick` (заморозить их 12 раз в секунду), `GAME.focus` (куда наклониться камере), `GAME.lights` (движущиеся фонари), `GAME.drawFx` (свои 2D-эффекты), `GAME.frame` (свои панели). Порядок — `hook(список, f, at)`. Локации (`src/world/map.js`): `LOC_HOOKS.objects` (добавить предметы после карты), `build` / `save` / `restore` (своё состояние каждой локации), `enter` / `leave` (на входе первым встаёт на место герой, потом остальные).
4. **Мишени и броски.** Стрельба целится в `hero.aimAt = { pos, state: 'up', onHit(away, hx, hy) }` — что делает попадание, решает игра. Бросок — приказ `{ type: 'throw', grab, release(rig), drop, prop }`.
5. **Запуск.** `whenReady('игра', boot)`, а в `boot(data)`: `buildDecals(); loadSaved(data, 'before'); enterLocation(data && LOCATIONS[data.loc] ? data.loc : 'id', 'start'); loadSaved(data, 'after'); setHero(buildHero(equip)); prepareStage(); startSaving(); runFrames();` — дальше цикл кадров движка. `data` — сохранение, с которого продолжить, или `null` для новой игры. Ручка для тестов — `window.__game`. Сменил снаряжение — `rebuildHero(); redraw();`.
6. **Состав.** `src/main.js` игры перечисляет все её модули по порядку: сначала ядро движка, потом нужные необязательные части, потом свои.

Самые короткие примеры: `ploshchadka/` (одно ядро и 50 строк игры) и `poligon/` (ядро, библиотека, машины и свои предметы).

## Сохранения

Игра сохраняется сама: при переходе в другую локацию, раз в минуту, когда страницу прячут или закрывают. В следующий раз она продолжается с автосохранения. Ещё три слота игрок заполняет сам, любое сохранение можно скачать в файл и открыть потом — это панель `src/ui/saves.js` в элементе страницы `id="saves"`. Хранятся сохранения в памяти браузера для этого сайта, отдельно для каждой игры.

Сохранение — один объект JSON: `{ v, game, saved, loc, parts }`. Его применяют только при запуске игры: «Загрузить», «Открыть файл», «Начать заново» перезагружают страницу, и она запускается уже с нужным сохранением — ничего построенного разбирать не приходится. Живое обновление страницы в Claude передаёт то же самое сохранение.

Что сохраняется — решает тот, кто этим владеет: каждый модуль добавляет свою часть `savePart(id, { phase, save() → данные, load(данные) })`. `phase: 'before'` — до постройки первой локации (кто где стоит, что у кого есть), `'after'` — после неё, до модели героя (где герой, во что одет, часы, камера). Сейчас части такие:

| Часть | Чья | Что в ней |
|---|---|---|
| `world` | `world/state.js` | память предметов и флаги |
| `clock` | `world/daytime.js` | день, час, идут ли часы |
| `hero` | `hero/state.js` | где стоит, куда смотрит, что надето (игра потом сверяет надетое со своими вещами) |
| `view` | `ui/hud.js` | ближе / дальше / вся локация |
| `machines` | `machine/machine.js` | где стоит каждый костюм |
| `inventory`, `people`, `talks` | `people/` | вещи героя; где каждый человек, в каком режиме, что у него; что кому уже говорили |
| свои | игра | например, `yard-items` двора — сколько осталось сигарет и банок |

Память мира `WORLD` хранит то, у чего нет другого хозяина: что было с каждым предметом каждой локации и флаги сюжета. `remember(inst, { searched: true })` — предмет запомнил (и сразу в `inst.dyn`, и в память; при следующей постройке локации память снова окажется в `inst.dyn`). Предмет узнаётся по ключу `inst.key` — тип и место на карте. `setFlag('имя', значение)` и `flag('имя')` — флаги и счётчики для разговоров и будущих заданий.

Формат меняется — растёт `SAVE_V`; сохранения новее формата игра не принимает, части, которые не подошли, пропускает, остальное загружает.

## Шагающие машины

Машина — это «вид» (`MACHINE_KINDS.ibk3`, `MACHINE_KINDS.b32`) и её состояние в `MACHINES`. Вид задаёт размеры, свои кости (`bones`), детали на костях (`build(put)`), поршни между костями, точки для посадки, тексты и два стиля — как стоит и где люк; всё остальное общее для любых машин:

1. **Кости.** Таз, корпус, ноги через IK (бедро → колено → голеностоп, стопа и носок), руки с пальцами — общие. Свои кости вида: у ИБК-3 башенка, люк с маховиком, заслонка; у «32» передняя капсула с рычагом и задвижками, мачта с датчиками, которая поворачивается и раскрывает коготь. Детали одной кости с одним материалом склеиваются в одну сетку.
2. **Посадка** — временная шкала стиля люка (`D.board.style`), назад — та же шкала задом наперёд. `rear` (ИБК-3): провернуть маховик, поднять люк, встать на ступеньку, на уступ, сесть на порог, съехать в кресло, задраить люк. `front` («32»): повернуть рычаг, поднять створку над головой, встать на колено машины, развернуться, сесть на порог спиной вперёд, поджать ноги в капсулу, притянуть створку изнутри. Руки героя держатся за точки на машине, позы — `poseBoard` в скелете (`seat` — кресло, `pod` — капсула с поджатыми коленями).
3. **Пробуждение и стоянка** — общее начало (огни, кашель двигателя, фары, заслонка или датчики, осмотр, проверка рук), дальше по стилю стоянки (`D.parkStyle`): `kneel` — встаёт с колена; `squat` — поднимается с корточек, не отрывая стоп, и переступает.
4. **Шаг.** Стопы стоят, пока не пришла их очередь; тело толкается вперёд, пока нога в воздухе, и проседает после каждого удара. Отсюда тяжёлый ритм: толчок, перенос, удар, осадка. Поворот на месте — переступанием. Удар стопы: тряска экрана, пыль или листья, след в текстуре земли, `MACHINE_HOOKS.stomp` для реакций игры (сигнализации машин).
5. Машина переходит между локациями вместе с героем и остаётся там, где он из неё вылез.

Корпус «32» — короб из колец с плоской крышей и выпуклой капсулой спереди (`splitHull` в `meshes`). Кольцо (`hullPoint`) может быть глубже и круглее спереди, чем сзади. Вершины колец расставлены так, что край проёма идёт по ним, поэтому капсула вырезана ровно. Очертание капсулы задаёт `open.half(y)` — полуугол проёма на каждой высоте (у «32» сужение посередине, где сидит фара), а насколько капсула выпирает из короба — `bulge(y, u, n)`. Отделка (рычаг, ручки, фара, стойки, рёбра внутри капсулы) ставится на поверхность короба или капсулы по высоте и углу, поэтому остаётся на месте, когда форму меняют.

Посмотреть машину со всех сторон: `node tools/machine-sheet.mjs лист.png --kind=b32`. Покадрово проверить анимацию: `node tools/sequence.mjs папка --setup="код" --dt=0.25 --n=24`.

## Договорённости

- Единицы — метры. Мир: `x` вправо-вниз по экрану, `z` влево-вниз, `y` вверх. Клетка карты — 1 м.
- Материал: `mat('#цвет', { pat, b, p, r, noise, grain, spec, gloss, thin, wind })`. `pat` — узор, `b` — второй цвет, `p`/`r` — параметры узора, `thin` — тонкое (трава): освещается с обеих сторон.
- Флаги у материала: `fl: 1` — без контура, `2` — активный предмет, `4` — мягкий контур (листва), `8` — становится прозрачным, когда заслоняет героя; `noShadow` — не отбрасывает тень.
- Гранёные корпуса (броня, кабины, бёдра) — `facets(кольца)`: стопка прямоугольников со срезанными углами вдоль оси, плоские грани.
- Предмет строится в своей системе координат (начало — на земле, `+z` — его лицевая сторона) через `Kit`, затем запекается в мир. `Kit.taper` — сужающийся стержень (ветки, стебли).
- Деревья растут в два шага: сначала скелет ветвей в условных единицах, потом он растягивается до нужной высоты и ширины кроны; комки листвы получают нормали, наклонённые наружу от центра кроны, — так крона освещается как одна масса.
- Следить за весом: дерево ~12 тыс. треугольников, весь двор ~230 тыс. Счётчик: `node tools/shoot.mjs папка --probe far`.

```
node tools/deps.mjs pyatietazhki                  # модули: без кругов, слои соблюдены, каждый импорт на месте, чужое не меняют

node tools/snap.mjs после --game=poligon --against=до   # …и после: совпадает ли до пикселя (и что стало с миром после шагов)
node tools/test-saves.mjs poligon                 # сохранения: поиграть, сохранить, загрузить, сравнить мир; файл; новая игра
```
